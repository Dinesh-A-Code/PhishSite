Connect your Gmail inbox

PhishSite never sees your password — Google handles sign-in directly and only hands this page a temporary, read-only token.

Needs a one-time, free OAuth Client ID from Google Cloud Console. How do I get one?

  1. Open Google Cloud Console and create (or pick) a project.
  2. APIs & Services → Library — search for and enable Gmail API.
  3. APIs & Services → OAuth consent screen — choose External, add your own Gmail address as a test user, and add the scope .../auth/gmail.readonly.
  4. APIs & Services → Credentials → Create Credentials → OAuth client ID — type Web application.
  5. Under Authorized JavaScript origins, add the exact URL you're serving this page from (e.g. http://localhost:8080), then save.
  6. Copy the Client ID and paste it above. This page must be served over http/https — sign-in won't work if you just double-click the file.

              Adversarial examples & failure cases

              • Polished, legitimate-like phishing — fluent AI phishing with a convincing footer is occasionally scored as Legitimate; mitigated by weighting URL and sender signals more heavily.
              • Tone-mismatched email — a human-written phishing email rewritten in a formal register drifts toward the AI-phishing class; flagged for adversarial retraining.
              • Short transactional emails — very short legitimate emails sometimes lack enough signal for a confident prediction.
